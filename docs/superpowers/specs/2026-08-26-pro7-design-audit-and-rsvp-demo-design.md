# PRO7 Design Audit, Admin Settings, and RSVP Demo Design

Date: 2026-08-26

## Goal

Bring the current PRO7 frontend into conformance with the accepted Checklist Design audit without redesigning the approved product, complete the missing Admin Settings and account-recovery surfaces, and prove the real Admin-to-player match invitation workflow with four temporary player accounts on Supabase.

## Product constraints

- Preserve the existing PRO7 information architecture, black/white/red palette, card geometry, controls, button order, and familiar desktop/mobile layouts.
- Do not reintroduce mock data into production components. Temporary test data is created in the connected Supabase project and remains clearly identifiable and removable.
- Server permission checks, RLS, and narrow RPCs remain authoritative. Hidden UI is never treated as authorization.
- Memberships are created directly by an Admin. There is no membership-invitation workflow.
- Match invitations are in-app notifications and deep links. Email/SMS delivery is not claimed because no production notification provider is configured.
- Do not execute destructive team deletion during browser verification.

## Experience design

### Responsive design system

The current PRO7 shell becomes the mobile/tablet shell at 900px, eliminating the broken 761–900px state. A semantic token layer defines primitive brand colors, surface/text/line/status tokens, type roles, spacing roles, control sizes, and component tokens for both themes. Residual green/neon declarations are removed. Meaningful labels and metadata use a readable minimum size, while purely decorative microcopy may remain compact.

Reusable modal behavior provides initial focus, focus containment, Escape close, and focus restoration. Forms expose dirty state, disable unchanged submits, report errors at the relevant field, and clear stale validation when corrected. Reduced-motion preferences disable non-essential transitions.

### Login and password recovery

Login adds an accessible show/hide-password control and a Forgot password link. Password recovery uses Supabase Auth's reset email flow with an allow-listed local callback, followed by a dedicated reset form that updates the authenticated recovery session. The existing temporary-password route remains the mandatory first-login flow for Admin-provisioned members.

### Notification center

The header bell becomes a real notification center backed by `public.notifications`. It shows the unread count, newest items, read state, and safe same-team deep links. Opening or selecting an item can mark it read through a self-only API boundary; RLS limits every read/update to the authenticated user.

Match invitation and reminder records are generated by the existing authoritative match RPCs. The player lands directly on the match detail and can answer Có/Không before the deadline. The Admin match detail shows each invited player's display name and response state: Có mặt, Vắng, or Đang chờ.

### Admin Settings

`/teams/[slug]/admin/settings` becomes a permission-gated dashboard with five modules:

1. Team profile: name and slug editing for callers with `team.update`.
2. Members and roles: roster counts, role/permission matrix, and direct links to the existing member CRUD surfaces.
3. Notification preferences: persisted team-level reminder preference JSON using `team_settings` and `settings.update`.
4. Audit log: recent redacted events from a new `SECURITY DEFINER` RPC that checks `settings.read`; the private audit table remains inaccessible directly.
5. Danger zone: a typed-confirmation team-delete control shown only with `team.delete`; browser verification never confirms deletion.

The migration enables RLS on `private.audit_events` as defense in depth, explicitly denies client table access, and exposes only the bounded/redacted audit RPC. Database advisors are re-run after applying it.

## Verification contract

- Every implementation change starts with a focused failing test.
- Unit/component tests cover strict parsing, permissions, notification boundaries, modal keyboard behavior, dirty state, and auth recovery helpers.
- SQL contract and disposable PostgreSQL tests cover RLS, grants, audit RPC, bounds, redaction, and rollback cleanup.
- Production build, rendered HTML tests, scoped lint/type checks, and diff checks pass.
- Browser verification is performed on `http://localhost:3000` using real Admin and Member sessions and the connected Supabase project.
- Supabase post-apply migration inventory and security/performance advisors are recorded.
